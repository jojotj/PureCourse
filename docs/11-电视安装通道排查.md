# 11 · 电视安装通道排查（TCL MT5879 / Android 11）

日期：2026-11-05
设备：TCL `tcl_mt5879_cn`，Android 11（API 30），**armeabi-v7a（仅 32 位）**，1920×1080 / density 240

---

## 1. 现象

```
adb install -r PureCourse-1.0.0-p0-armeabi-v7a.apk
Failure [INSTALL_FAILED_VERIFICATION_FAILURE]
```

`pm install`、`pm install --skip-verification`、`pm install -i com.android.packageinstaller --user 0`
全部同样的错。系统里"允许安装"的开关一开始就已经是开的：

```
package_verifier_enable = 0
verifier_verify_adb_installs = 0
install_non_market_apps = 1
unknown_sources_default_reversed = 1
```

## 2. 关键一步：先做通道对照，别急着改包

用**同一台电视上已经装着、用户确认能正常使用**的两个 APK，走同样的 `adb install`：

| APK | 结果 |
|---|---|
| 我们的 `PureCourse` | `INSTALL_FAILED_VERIFICATION_FAILURE` |
| 小黄人 TV v2.9.5（同一台电视上已装） | **同样报错** |
| 奇异果 TV v3.46（同一台电视上已装） | **同样报错** |

再看它们当初是谁装的：

```
com.ds.xhrtv  installerPackageName=com.android.packageinstaller
com.ds.gitv   installerPackageName=com.android.packageinstaller
```

**结论：这台电视的 `adb install` / `pm install` 通道被 TCL 在框架层封死了，
跟 APK 本身无关。** 上面那些"能装"的应用都是走电视界面的系统安装器装的。

> 这是本轮最重要的一条方法论教训：**在改包之前，先验证"通道"通不通。**
> 我一开始按 targetSdk、签名方案、minSdk 逐项猜，改了三轮都是白改，
> 直到拿一个已知能装的包做对照才定位到真因。

## 3. 日志线索

```
D OverseasAppConfig: Verifying begin
D OverseasAppConfig: pkgName = com.chunting.purecourse
```

`OverseasAppConfig` 在 **system_server 进程内**（pid 579），是 TCL 改的 framework 模块，
不是可禁用的独立包。它只记录，不打印拒绝原因。

另外 TCL 也改了 ActivityManager：`am start -n com.android.packageinstaller/.PackageInstallerActivity`
直接抛 `SecurityException: not exported from uid 10011`（该 Activity 未导出，shell 起不来），
`ITclActivityManagerEx_StubTcl` 在拦截。设备是 production build，adb 无法 root（`adbd cannot run as root`）。

所以**没法从 adb 侧绕过，只能用电视自己的安装器**。

## 4. 顺手对齐参数（降低安装器侧的风险）

虽然根因是通道，但既然改了一轮，就把参数对齐到"同一台电视上实测能装"的那几个包：

| 项 | 改前 | 改后 | 小黄人（能装） | 奇异果（能装） |
|---|---|---|---|---|
| minSdk | 26 | **21** | 21 | 21 |
| targetSdk | 36 | **34** | 34 | 34 |
| v1 签名 | **无** | **有** | 有 | 有 |
| 包体 | 34.8MB | **12.4MB** | 3.0MB | 148KB |

三项改动的真实原因：

1. **补 v1 签名**。AGP 8 在 `minSdk >= 24` 时默认只出 v2；旧包解压后**没有任何 `META-INF/CERT.SF`**。
   注意 `apksigner verify` 会报 `Verified using v1 scheme: false`，那是**报告语义陷阱**——
   它按 manifest 的 minSdk 判断"这个版本不需要 v1"就不去验证，不代表包里没有。
   判断有没有 v1 要直接看 zip 里有没有 `META-INF/*.SF`。
   显式 `enableV1Signing = true` 后产物里就有了。
2. **targetSdk 36 → 34**。API 30 设备上 36 没有任何收益；厂商安装器对"比系统新很多的 targetSdk"
   可能有额外判定，对齐 34 更稳。
3. **移除 libmpv**（34.8MB → 12.4MB）。PoC 已证明 Media3 够用（FLV/H.264/AAC 实测全通），
   而 libmpv 强制 minSdk 26 并带来约 22MB 的 ffmpeg/mpv 原生库。
   移除后 minSdk 可降到 21，与同机能装的包完全一致。
   `MpvEngine.kt` 已删，`PocBench` 只保留 Media3 臂（换设备时可一键复测）。

## 5. 后续怎么装

**U 盘 + 电视自带安装器**（已把包拷到 U 盘根目录）：

```
课程库-1.0-TV(装这个).apk        12.4MB  armeabi-v7a ← 这台电视用这个
课程库-1.0-TV-64位(备用).apk     12.4MB  arm64-v8a
```

电视上的操作路径（TCL 常见两种，任选）：
- 插 U 盘 → 电视弹出"检测到 USB 设备" → 打开"媒体中心/文件管理" → 找到 apk → 确认安装
- 或打开已装的「当贝市场」→ 管理 → 本地安装 → 选 U 盘里的 apk

## 6. 装上之后能不能远程调试

**能，而且现在就能。** 被拦的只是"通过 adb 安装 APK"这一个动作，其余 adb 能力全部正常：

| 能力 | 状态 |
|---|---|
| `adb shell` 任意命令 | ✅ |
| `adb exec-out screencap` 截图 | ✅ |
| `adb shell input keyevent` 模拟遥控器 | ✅ |
| `adb logcat` 抓日志 | ✅ |
| `adb push/pull` 文件（含 /sdcard） | ✅ |
| `dumpsys` 查状态 | ✅ |
| `adb install` | ❌ 被 TCL 封 |

所以只要用 U 盘装上一次，后面所有 UI 验收、遥控器链路测试、播放联调、崩溃排查，
我都可以直接在这台电视上做，不需要你在旁边点。

## 7. 后续实测补充（2026-11-05，已验证）

- ✅ **U 盘 + 电视系统安装器装成功**：用户已确认；设备上
  `dumpsys package com.chunting.purecourse` → `versionCode=1 / versionName=1.0.0-p0 /
  firstInstallTime=2026-11-05 14:53:17`。12.4 MB 的 32 位包未被拦，原先的两条疑问均销项。
- ✅ 原先列的真机复测项已全部完成：Media3 在 MT5879 上走 `OMX.MS.AVC.Decoder` 硬解、
  真实 SMB 播放、seek、1080p 观感、起播 / 1x / 2x 帧率与掉帧、TV 输入法、遥控器、稳定性，
  详见 [`docs/12-电视真机专项验收.md`](12-电视真机专项验收.md)。
- 🆕 **结论收窄**：本轮又试了**不同于 `adb install` 的通道**：

  ```
  adb push <tv2.apk> /data/local/tmp/purecourse-tv2.apk          # 成功，12485350 B
  adb shell pm install -r /data/local/tmp/purecourse-tv2.apk
  → Failure [INSTALL_FAILED_VERIFICATION_FAILURE]
  ```

  即 TCL 封的是 **PackageManager 侧整个 ADB/shell 安装通道的验证环节**，
  不只是 `adb install` 命令；换 `pm install` 本地包同样不通（`docs/evidence/tv-pm-install.txt`）。
  因此后续新版本仍需 U 盘系统安装器，或换手机用 ADB 安装。
- ⚠️ 命令坑复现：Git Bash 会把 `/data/local/tmp/...` 做 MSYS 路径转换，
  `adb push` 前必须 `export MSYS2_ARG_CONV_EXCL='*'`（docs/09 已记录同类问题）。
- 🆕 **2026-11-05 16:20 第三次收窄**：又试了 `content://` + 系统安装器 intent：

  ```
  am start -a VIEW -d file:///sdcard/Download/purecourse-tv3.apk \
           -t application/vnd.android.package-archive
    → No activity found（Android 7+ 已移除 file:// 安装入口）

  content query --uri content://media/external/file → _id=5442
  cmd package resolve-activity -a VIEW -d content://media/external/file/1 \
           -t application/vnd.android.package-archive
    → com.android.packageinstaller/.InstallStart（可解析）
  am start -a VIEW -d content://media/external/file/5442 \
           -t application/vnd.android.package-archive --grant-read-uri-permission
    → Intent 发出，但安装界面静默消失、无 UI、版本不变
  ```

  即 **TCL 封的是 PackageManager 验证环节**，连系统安装器 intent 也走不通；
  唯一可用仍是 **U 盘 + 电视自带安装器**，或换手机 `adb install`。原始输出见
  `docs/evidence/tv3-installer-content.txt`。
- **用户明确要求（2026-11-05）：不再向电视推送任何文件**——电视自带安装器看不到
  `/sdcard/Download` 等目录，推送无意义。此前推送的 6 个 APK / 临时文件已全部删除并复核，
  清单见 docs/14 §1。后续交付只放 `dist/`，由用户用 U 盘 + 电视系统安装器安装。

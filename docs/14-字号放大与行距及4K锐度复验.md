## 3. 「模拟器清楚、电视发糊」的决定性判别

### 3.1 原始帧里的字**不糊**（可核验，非推测）

电视 `screencap -p` 输出 **1920×1080**；裁左上文字区 `crop=760:230:50:130` 后用
`scale=3040:920:flags=neighbor` **4 倍最近邻放大**（`docs/tv4-02-fav-zoom4x.png`）：
「收藏目录」「courses（SMB 根目录）」「考研 / 408 专业课」的中文笔画是**硬边像素块**，
边界分明，只有抗锯齿必需的少量中间灰阶。设置页同样处理（`docs/tv4-05-settings-zoom4x.png`）结论一致。

> 即：App 在 1080p 画布上栅格化出来的文字是清晰的，模糊**不在 App 渲染阶段**。

### 3.2 模糊发生在显示输出阶段（硬件 dump）

```
[vendor.display-size]: [3840x2160]                  ← 物理面板 4K
DisplayDeviceInfo{... 1920 x 1080, density 240}     ← Android 只给 App 1080p
supportedModes = [{id=1,1920x1080,50Hz},{id=2,1920x1080,60Hz},
                  {id=3,1920x1080,100Hz},{id=4,1920x1080,120Hz}]
mBaseDisplayInfo real 1920 x 1080 / largest app 1920 x 1080

HWComposer Primary Display[0] Type: Physical
   3840 x 2160 | 3840 x 2160 | 120 | 1920 x 1080
Layer {SizeType[7], LayerW:LayerH|DstW:DstH[0:0|1920:1080|3840:2160]}
```

链路：矢量字 → **按 1920×1080 栅格化成位图** → MTK HWC 把整张位图插值放大 **2× 到 3840×2160** → 面板。
「矢量字体 4K/1080P 清晰度一样」的前提是**系统把 4K 画布给 App**，这里不成立；
而且 4 个 `supportedModes` **全是 1920×1080**，App 连申请 4K 显示模式的入口都没有
（`minimalPostProcessingSupported=false`，也没有逐窗口的最低后处理开关）。

### 3.3 本轮新增：模拟器为什么清楚（定量对照）

| | TCL 电视 | MuMu 模拟器 |
|---|---|---|
| `screencap` 原生尺寸 | 1920×1080 | **2560×1440** |
| `StageCanvas` 的 `fit` | **1.000** | **1.333** |
| `Density(fit, 1f)` 下 `20.sp` 栅格化 | **20 px** | **26.7 px** |
| 显示链路 | 1080p → HWC **2× 插值** → 4K 面板 | 2560×1440 **1:1 直出** |
| 结果 | 源像素少 25% + 二次插值 | 源像素多 33% + 无插值 |

用户给的三张标注图实测均为 `2559×1439`（≈ MuMu 的 2560×1440），正是"清楚"的那一侧。
所以差异不是错觉，也不是 App 的 bug：**电视侧每个笔画可用的源像素更少，之后又被位图放大一次**。

### 3.4 系统层线索（只读探测，**未验证、未改动**）

```
settings list global → persist.tcl.cyberui.is4k=false
```

这是 TCL 系统 UI 的 4K 标志位，可能与"UI 是否按 4K 渲染"有关。改动系统设置需要重启、
影响全系统其它应用，本轮**没有动**。若你愿意试，我单独做一次可回滚的验证。

### 3.5 App 侧能做的只有一件事：放大字号

放大字号 = 让每个笔画在 1080p 层占更多源像素，2× 放大后灰阶边缘占比下降，观感变锐。
本轮把红框区域的字放大了 **+15% ~ +24%**（见 §4），这是唯一在 App 内可控的杠杆。
**本轮没有改颜色、没有改渲染管线、没有动系统分辨率。**

## 6. 未验证 / 待你裁决

| 项 | 说明 |
|---|---|
| **tv4 在电视上的实际观感** | 需要 U 盘装 `dist/课程库-1.0-TV-tv4(装这个).apk`；U 盘 `H:` 当时未插入，我无法代拷 |
| **全局文字放大旋钮** | `StageCanvas` 的 `Density(fit, 1f)` 改成 `Density(fit, 1.15f)` 可让**全站**文字再大 15%（`dp` 布局不动），锐度也会再好一点；风险是固定高度文本框（剧集卡、按钮）可能需逐个复核裁切。本轮**未做**，等你定 |
| **只对电视放大** | 也可写成 `if (fit < 1.2f) 1.15f else 1f`，电视放大、模拟器维持现状；但会引入设备差异 |
| **低对比辅助字提亮** | `C.Dim2 (#7A716A)` → `C.Dim (#A89E94)` 能改善小灰字在 2× 放大后的"糊感"；属于视觉设计改动，本轮**未做** |
| **系统 4K UI 开关** | `persist.tcl.cyberui.is4k=false`，未验证、未改动；改动需重启且影响全系统 |
| 其余历史未验证项 | 长按 800ms、真实休眠唤醒、HDMI ARC/功放直通、P4 占满 20 条并发失败层 UI |

诚实边界：§3.1 的"原始帧清晰"来自 ADB `screencap` 的像素级放大，**不是我用相机拍电视屏幕**；
§3.2 的 HWC 放大是 `dumpsys SurfaceFlinger` 的原文，属硬件事实；§3.5 的"观感会变锐"是
基于源像素占比的推论，**尚未在装上 tv4 的电视上主观确认**。

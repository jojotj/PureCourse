## 2.0.7 - 2026-11-10

### 画面比例：按 DAR（含采样宽高比）出画，不再裸用 width / height
- `VideoSize.width/height` 是未修正的存储像素尺寸；老课程片常是 `1440×1080 + SAR 4:3`，
  裸像素比 4:3、真实显示比 16:9，旧逻辑把这类片横向压窄（电脑上 VLC / PotPlayer / MPV
  都按 DAR 出画，所以同一文件在电脑上正常）。
- `Media3Engine` 的比例回调改为返回 `DAR = width × pixelWidthHeightRatio / height`
  （`par ≤ 0` 或 NaN 兜底 1f），播放页用该比例约束画面容器，等比居中、不拉伸。
- 实测「泉灵语文写作.一年级」41 集：SAR 1:1 共 36 集、4:3 共 4 集（第 01/02/05/10 课）、
  753:565 共 1 集（第 03 课），修复后各集比例均正确。

### 控制层蒙版位置修正
- 顶部课程信息蒙版原先带 `padding(top = 104.dp)`（页面态给顶栏留的空白）。画面区改成
  全屏后，这条蒙版整体下沉 104dp，视觉上像是「蒙版跟着视频比例跑」，实际是残留偏移。
- 现改为独立一层：**固定 300dp 高、从屏幕最顶端 0dp 开始铺渐变**，标题文字浮在其上，
  不再随标题占 1 行 / 2 行而变高。蒙版位置与视频宽高比、分辨率、显示位置完全解耦。
- 控制层态的暂停符由 `top = 246.dp` 调为 `330.dp`，落在蒙版下方。
- 模拟器实测（2560×1440）：顶部渐变自 y=0 起、y≈400px 处完全透明；底部控制层贴底完整显示。

### dist 归档
- `PureCourse-2.0.7-{arm64-v8a,armeabi-v7a}.apk`、`PureCourse-2.0.7-clean-{arm64-v8a,armeabi-v7a}.apk`。
- `versionCode 35`，签名与前版一致，可覆盖安装保数据。

## 2.0.4 - 2026-11-09

### 新增「干净包」：拆 flavor，靠源集隔离而不是运行期开关
- `app/build.gradle.kts` 新增 `preset` 维度两个 flavor：
  - `local` —— 自用包，带本机真实 SMB 配置与快捷位置（源码 `app/src/local/.../BuiltinPresets.kt`）；
  - `clean` —— 发布包，`app/src/clean/.../BuiltinPresets.kt` 里全是空值 / 空表。
- 关键点：**真实 IP / 账号 / 共享名在 clean 变体里根本不参与编译**，dex 里搜不到。
  早期用 `-P` 参数 + `BuildConfig.CLEAN_BUILD` 在运行期短路时，字符串常量仍留在 dex 常量池，
  反编译即可读出 192.168.1.10 与 guest/guest，故改为源集隔离。
- 干净包首启状态：数据源列表只有内置的「本地存储」，没有 SMB 源、没有快捷共享位置，
  书架 0 门课程；全部由用户自己「添加数据源」。
- `SMB 端口`（445）等表单默认值保持不变，不属于本机数据。
- `SourceStore.ensureDefault` 在 clean 变体下直接短路，不写任何默认源。
- dist 归档按 flavor 分别命名：自用 `PureCourse-2.0.4-<abi>.apk`，干净 `PureCourse-2.0.4-clean-<abi>.apk`。
  两者包名、签名（证书 SHA256 CE:5F:17…B65E）、versionCode(32) 完全相同，可互相覆盖安装且不清数据。

## 2.0.3 - 2026-11-09

### 已看标记改为按集记录
- `Course.doneEp: Int` 改为 `Course.doneSet: Set<Int>`，`doneEp` 变成集合大小（只读派生）。
  以前「已看集数」是 `curEp - 1` 推出来的，于是在详情页跳到第 50 节看一眼，前 49 节立刻全变成「✓ 已看」。
- 只有**真的播到片尾**（`leavePlayerAfterEnd`）或**手动按下一集**（`stepEp(+1)`）才把那一集记为已看；
  回看旧课（往前翻）不改进度。新增 `AppState.markDone(courseId, ep)` 统一入口。
- `CourseMetaStore` 持久化格式追加第 4 段「已看集号列表」（逗号分隔），旧记录读出来是空集，不会误标。
- 详情页剧集状态：`current` 优先于 `done`，同时满足时显示「✓ 已看 · 当前集」。
- 「下次打开直接进去」仍然靠 `curEp` + 详情页「继续播放 第 N 节」，只记录最后看的那一集。

### 列表滚动改为焦点居中（tvOS 范式）
- `ensureIndexVisible`（LazyList / LazyGrid 两版）重写：把焦点项中心与视口中心的差值交给
  `scrollBy`/`animateScrollBy`，**光标框停在屏幕中间不动、背后内容走**；滚到首/尾时 Compose 自己 clamp，
  光标才跟着往上/往下挪 —— 取代原来「滚到目标项顶对齐」的翻页式滚动。
- 覆盖范围：书架、浏览、收藏、设置、详情页剧集宫格，以及数据源页（此前数据源页完全没有滚动绑定，已补上
  `rememberLazyGridState` + 焦点映射）。
- 设置页去掉「额外把组标题再滚一次」的补丁，居中滚动后焦点行上下各留半屏，最后一行不会再被顶出屏幕。

## 2.0.1 — 2026-11-08

两处导航缺陷修复；同时把「发版产物归档」做成构建期自动动作，不再手工拷包。

### 修复

- **跨源同名目录被误判成「已在书架」**：原 `onShelfKey` 在按「源 id + 源内路径」查不到时会退回**按目录名兜底**，
  于是两个数据源只要存在同名目录（例如都叫 `guest`），A 源已加入书架就会让 B 源的目录在浏览页也显示「已在书架」，
  点「移出书架」又找不到对应条目。现在新增 `sameShelfPath` / `relKey`，`shelfCourseOf()`、`addToShelfByNode()`
  一律按「源 id + 源内路径」判定，`onShelfKey` 删除按名兜底——书架归属只在同一源内成立。
- **左树收起未清零子层展开状态**：四处 `ftOpen` 收起动作原来只清自身一层，子层 key 仍留在展开集合里，
  再次展开父层时整棵子树会「自己弹开」，与收起前的状态不一致。新增 `closeNode(key)` 按 key 前缀清空整棵子树，
  替换 `KeyRouter.kt`、`Nav.kt` 里的四处收起点。

### 构建与发版

- **版本号收敛为单一真源**：`appVersionName` / `appVersionCode` 定义在 `app/build.gradle.kts` 顶部，
  `defaultConfig` 与 dist 归档命名共用，以后发版只改这两行。
- **新增 Gradle 任务 `copyReleaseApksToDist`**（`distribution` 组），挂为 `assembleRelease` 的 finalizer：
  构建结束后自动把 `armeabi-v7a` / `arm64-v8a` 两个单包按 `dist/PureCourse-<versionName>-<abi>.apk` 落进工程根 `dist/`，
  同名覆盖、跳过 `x86_64`（仅模拟器调试用）、不触碰 dist 里的历史版本包。

## 2.0.0 — 2026-11-08

数据层重写：把"开机扫全树"换成"点哪层读哪层"。这是 2.0 唯一的大改动，其余为公开化整理。

### 为什么改

1.0 冷启动对数据源做 BFS 全树扫描（上限 420 次 `PROPFIND` / 深度 4）。在 OpenList、115 这类
服务端上单次 `PROPFIND` 要几百毫秒到数秒，420 次 = 几分钟：

- 书架长时间空白；
- 扫描线程与浏览请求抢同一条 HTTP 通道，点进文件夹要排队；
- 每回来一批结果就整体替换节点表，正在看的目录被抹掉又重建（闪烁）。

### 数据层

- **启动只读根目录一层**（`DavCatalog.scan`），1 次请求铺满浏览页第一屏，不再全树递归。
- **书架每门课只读自己那一层**（`fetchAll`，并发 6 路），只判断该层有没有视频，绝不递归；
  `snapshotOf()` 复制集合后整体发布，避免读取过程中 UI 拿到半张表。
- **点开书先显示后刷新**（`AppState.refreshCourseDir`）：先用手里的集数立刻进详情页，
  后台重读该层；清单未变则完全不碰 UI，失败静默保留旧清单。
  新增 `refreshingDirs` 做并发防护，同一目录不会被点几次就读几次。
- **WebDAV 不再读写目录缓存**（`scan` 与落盘处都排除 `Proto.DAV`）：源上目录常改名删除，
  跨天缓存里的路径点进去必然 404；既然只读一层，这份缓存也不再是提速必需品。
- **书架为空的判据修正**：原判据「节点数 > 1」在只读一层后恒等于 1，
  会把正常空书架误判成读取失败并盖红字。改为「没有任何源报错即视为数据源通」。

### 网络层

- **浏览 / 播放分池**（`DavClient`）：新增独立 `browseClient`（`maxRequestsPerHost=6`、
  读超时 15 s、禁重试、复用同一套 trust-all 配置），浏览请求不再排在播放连接后面；
  播放继续走原通道，pause / seek 不受目录读取影响。
- **目录 URL 统一补尾斜杠**（`urlOfDir`）：避免服务端把 `/dav/course` 301 到 `/dav/course/`
  时白跑一次重定向。
- `list()` 走浏览池，`fetchAll` 的并发度与服务端承载对齐（6 路，非 420 连发）。

### 仓库结构整理（尚未发布）

- 目录按 GitHub 公开仓库的标准形态铺好：源码 `app/`、发布包 `dist/`、文档 `docs/`、
  签名 `keystore/`（仅留说明），补 `.gitignore` / `.gitattributes` / `LICENSE`。
- 重写根 `README.md` 作为仓库首页；1.0 时期的 README 原文归档为
  [`docs/README-legacy-1.0.md`](README-legacy-1.0.md)。
- **本版不做脱敏**：`RealCatalog` 仍保留本机真实默认共享（`192.168.1.10` / `guest`），
  方便真机联调时首启即有数据源。对外发布前需要执行的清理动作全部列在
  [`PUBLISHING.md`](PUBLISHING.md)，联调完成后再统一处理。

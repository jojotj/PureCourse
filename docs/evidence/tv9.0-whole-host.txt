tv9.0 · 一个 IP 一个数据源（整机模式）+ 左树可浏览
==================================================

一、用户提出的问题（原话）
--------------------------
1. "SMB 一定要有路径才能访问？光打一个空斜杠不能访问到后面所有文件夹。"
2. "读出来以后我右边只能选其中的一个，当我的 IP 固定的情况下面，前端也只能显示一个数据库。
    每次改数据库要重新到编辑里换一个共享目录，这个逻辑不对。"
3. "应该是不用我选其中一个，跳出来就是所有的共享目录在左边，左边可以浏览目录，
    右边可以把某一个子目录或者直接就是根目录添加到收藏或者书架。"
4. "数据源点进去，假设我现在是 SMB 共享，那左边的目录数就应该有我共享的 4 个目录。"

二、为什么以前只能是一个共享
----------------------------
* SMB2 的 `TREE_CONNECT` 必须带共享名，协议里没有"连接主机根"这回事；
  `smb://host/` 要列出共享，得走 srvsvc 的 `NetrShareEnum`（管理面 RPC，走 IPC$ 管道），
  不是文件系统操作。所以"留空路径"本身不可能凭空列目录，必须先枚举。
* 旧实现把 `Cfg.share` 当成数据源的根：一个数据源只能挂一个共享，
  浏览树的第一层是"共享内的一级目录"，共享名根本没出现在界面里。
  → 同一台电脑有 4 个共享，就得开 4 个数据源；换共享要进编辑页重填。

三、tv9.0 的改动
----------------
1. **数据源 = 整机**：`Cfg.share` 允许为空，空 = 整机模式（`wholeHost`）。
   添加数据源时"共享 / 路径"留空 → 保存后一个 IP 就是一个数据源。
2. **统一路径语义**：所有 rel 一律 `共享名\共享内路径`（如 `于斯课堂\02 乐理课程`）。
   `Cfg.splitRel()` 负责拆分，`uriOf/uncOf` 按整机/单共享两种模式拼 smb:// 与 UNC。
3. **会话层支持切共享**：`SmbSession.useShare(name)` 只 close 旧 `DiskShare`、
   复用同一个 SMB 会话去 `connectShare`，毫秒级，不重连。
   `connect(host, "", ...)` 只建会话不挂共享；`isConnected` 改成看 session。
4. **扫描两类模式**：
   - 整机：先枚举共享，再对每个共享做"一级目录 = 课程"的展开，节点 key 是 `共享名`；
   - 单共享：保持原逻辑（兼容用户手工指定一个共享）。
5. **浏览页左树 = 真实目录层级**（`AppState.browseRows()`）：
   之前左树只渲染 `favs`，所以只有"全部共享"一项，等于不能浏览。
   现在沿 `browseStack` 逐层展开，缩进显示；确认即跳到该层。
6. **播放切共享**：`SmbDataSource` 按 URI 第一段 `useShare`，整机模式下跨共享播放不会串。
7. **加入书架落盘**：`SourceStore.shelfPaths/addShelfPath/removeShelfPath`，
   冷启动由 `RealCatalog.addShelved()` 重新读成课程（之前只改内存，重启即丢）。
8. **枚举重试**：`SmbShares.list()` 对 `STATUS_PIPE_NOT_AVAILABLE (0xC00000AC)` 重试 3 次
   （反复进出 App 时 srvsvc 管道可能还没被服务端回收，实测会撞上）。
9. **旧配置一次性迁移**：只把"完全等于旧默认值（于斯课堂 / 02 乐理课程）"的配置
   升级成整机模式，用户自己改过的一律不动。
10. **空目录提示**：浏览空文件夹显示"这个文件夹是空的"，不再一片空白。

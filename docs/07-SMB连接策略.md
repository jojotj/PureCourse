# 07 · SMB 连接数：能查什么、能清什么、怎么少占

> 对应老板提的三问：① APK 能不能查出自己跟 SMB 主机建了几条连接？② 能不能从 APK 端清零？
> ③ 能不能"一条连接一直用"，而不是一个 APK 占好几条？
> 本文只讲结论与依据，实现见 `data/SmbSession.kt`（P1 换成 smbj 实现，接口不变）。

## 1. 能查什么（明确边界，不吹）

| 想查的 | 能不能 | 依据 |
|---|---|---|
| **本播放器自己开了几条** | ✅ 能 | 客户端自己持有 `Session` 对象，数一下就是。日志/诊断层显示的就是这个数 |
| 服务端**总共**被占了几条（含别的设备、含僵尸会话） | ❌ 不能 | SMB 协议**没有**"查询服务端会话表"的客户端命令。`net session` 是 Windows 本机的管理 API，不是 SMB 协议的一部分 |
| 服务端是不是"已经满了" | ⚠️ 只能间接判断 | 用错误码推：`STATUS_REQUEST_NOT_ACCEPTED` / `0xC00000C9` / 认证通过但读 0 字节 → 判为会话满（§5.5 的分类表） |

> 有人会说"用 WinRM/WMI 远程跑 `net session` 不就行了"——那需要 Windows 管理员账号密码，属于越权操作，
> 而且要把管理员凭据存进电视 App，安全上不可接受。**不做。**

## 2. 能清什么

| 想清的 | 能不能 | 做法 |
|---|---|---|
| **本播放器占的会话** | ✅ 能，且立刻生效 | `session.close()` → 服务端那条会话随即释放，**不用等 15 分钟空闲回收**。这就是诊断层里「断开本机全部会话」按钮做的事 |
| 别的设备（手机/另一台电视）占的 | ❌ 不能 | 客户端无权断别人的会话 |
| 异常退出留下的僵尸会话 | ❌ 不能 | 只能等超时回收，或在电脑上跑 `net session /delete /y`（桌面那个 bat） |

**所以"从播放器端把连接数清零"这句话要拆开看**：能清"自己那份"，清完自己的，服务端就少一条；
但如果电脑上显示 20 条满、其中 18 条是历史僵尸，那电视端清完也还是连不上 —— 这时只能去电脑跑 bat。
这也是为什么诊断层里两个动作必须并存：**「断开本机全部会话」+「我已清线程，重新连接」**。

## 3. 怎么少占连接（设计结论）

### 结论：**一条会话长期复用**，不是"每次进出都断开重连"

用户直觉是"退出视频就断开、进新视频再连"，听起来更干净，但实测与协议层都指向反面：

| 方案 | 稳态会话数 | 代价 |
|---|---|---|
| 每次进出重连 | 1 条（但频繁 churn） | 每次重连 100~300ms；失败时容易连环重试；服务端更易残留半开会话；更容易撞上"连接数已满" |
| **单例复用 + 空闲断开**（本工程采用） | 1 条 | 几乎没有额外代价；空闲到点自动释放，不长期占用 |

### 具体规则（P1 落地）

1. **全局单例**：整个 App 只有 1 个 `SmbClient` + 1 个 `Session`，浏览目录与播放**共用**。
2. **切集不新建**：同一门课切上/下一集，复用同一个 `TreeConnect`，只换文件路径。
3. **引用计数 + 空闲释放**：播放页进入时持租约（lease），退出时释放；引用归零后**空闲 N 秒**才真正 close。
   - 默认 N = 30 秒（进下一集/返回再进不会重连）
   - 想"退出就断"：把 `idleReleaseSec` 设为 0（P1 在诊断层给开关）
4. **失败退避**：1s / 2s / 4s，上限 3 次，禁止狂重连（狂重连会瞬间吃满 20 条）。
5. **自控上限 ≤2**：正常应该恒为 1；出现 2 说明有一个连接没释放，诊断层会标红提示。
6. **判满升级**：连续 2 次读失败 → 自动弹诊断层（不静默黑屏）。

## 4. P0 现在给了什么

诊断层已经能看到并操作（`g-23-smbdiag.png`）：

```
本机 SMB 会话   0 条（尚未接入 SMB，P1 起显示真实值）
释放策略：退出播放页后空闲 30 秒断开 · 最近释放 —
说明：这里只能清掉「本播放器」占的会话，电脑端其他设备与僵尸会话清不掉，仍需在电脑上跑那个 bat。
[ 断开本机全部会话 ]   [ 去数据源重连 ]   [ 先关掉 ]
```

- `SmbSession` 已经是可调用的真实对象（计数、释放时间、租约、`disconnectAll()`），
  P1 只需把 `disconnectAll()` 里的注释位替换成 `session.close()`，UI 与遥控器逻辑零改动。
- **不假装**：没接 SMB 就明写"尚未接入"，不编造"已连接 1 条"。

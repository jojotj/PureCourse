## 1. 这次要解决什么

此前 App 只能有一条数据源：保存 WebDAV 会覆盖 SMB，书架、收藏、续播全部围绕"唯一源"设计。
本次把数据模型改成**一组源并存**，并解决由此派生的三个具体问题：

1. 路径必须能区分来源 —— 用 `@<源ID>\` 前缀（`@s1\课程共享\乐理`，根路径就是 `@s1`）。
   分隔符选 `@` 而不是 `/`，因为 `#fav` / `#c5` 已经是收藏页伪节点的 key。
2. 两个源里可能都有「钢琴课」这种同名目录 —— 靠**来源标签**（`SMB · 本机SMB` / `DAV · 115网盘`）+ **备注名**双重区分。
3. 旧数据（无前缀）冷启动一次性迁移到首个源，覆盖 `shelf_paths` / `fav_paths` / `removed_paths` / 课程元数据 / 续播键。

## 4. 自查中发现并修掉的 4 个问题

这一节是这次交付的重点：以下四个都是**我自己写出来的**，靠"跑一遍 + 看文件 + 看画面"抓到的。

### ① 备注名存了、界面不动（三个位置全漏）

- 现象：`purecourse_alias.xml` 里已经有记录，左树和右栏仍是原名。
- 根因：`setAlias` 只改了 `courses` 和 `fs[k].name`。
  而收藏页的**左树行与右栏标题读的是 `favs`**，**展开后的子目录行读的是父节点里的 `FsItem`**，
  三处都不是"节点自身的 name"。
- 修：`setAlias` 同步改 `courses` / `fs` 节点名 / `fs` 子项名 / `favs` / `sources`；
  `buildMerged` 与 `ensureNode` 构建 `fs` 时统一套 `aliasMap`。

### ② 部分扫描结果覆盖缓存全量 → 书架"课程消失"

- 现象：冷启动 12 秒内 314 门 → 掉到 27 门（只剩 SMB 的），几分钟后再涨回来。
- 根因：`DavCatalog.scan` 的 `onPartial` 回调无条件 `snapBySrc[cfg.id] = partial`。
  缓存里是上次的 302 门，部分结果是"刚开始扫到的 0~15 门"，一覆盖就把全量顶掉了。
- 修：新增 `cacheSnapBySrc`，**有缓存时不允许部分结果覆盖**；无缓存（首次扫描）才边扫边显示。
  实测复测：冷启动 8 秒即显示 `314 门课程 · 5030 个视频`，全程不缩水。

### ③ 备注名会被"写进"收藏表 → 清掉改不回来

- 现象（代码审出，未等它发作）：`addFav` 落盘的是 `item.name`，而此时 `item.name` 已被套上备注名；
  一旦用户清空备注，`buildMerged` 回落读到的还是那个备注名，名字永久粘住。
- 修：落盘存 `realNameOf()` 推出来的真名，显示才用 `aliasMap`；`realNameOf` 对根路径补了回退到数据源显示名（原来会返回空串）。

### ④ 每帧重读全部 prefs（性能）

- `publishMerged` 每次都要 `CourseMetaStore.loadAll`，而边扫边推会 publish 几十次。
- 修：`metasCache` 内存缓存，`touchCourse` 时置空。

## 5. 遗留问题（已知、未修、需知情）

1. **DAV 全量扫描 6~7 分钟**（115 网盘单次 PROPFIND 约 7 秒）。首次配置或换源时书架只有缓存内容/部分内容，属预期行为，界面有「已发现 N 门课」进度提示。
2. **`SmbSession` 仍是全局单例**：两台不同 SMB 主机的片子在播放时会互相重连。已加"按主机自动重连"兜底，但**没有实机双 NAS 环境验证**；同一时刻只会有一个 SMB 会话。
3. **备注名输入中文依赖电视输入法**：adb 无法注入中文，本次实测用的是英文 `Music-DAV` / `Piano-115`。中文输入路径未实测。
4. **本地源（SAF / File）仍未实现**，数据源页保持「尚未实现 · 当前已接入 SMB 与 WebDAV」的诚实文案。
5. **删除数据源后 `AliasStore` 里该源的备注名残留**（不清扫）。因为 `newId` 序号只增不减，`@s1` 不会被复用，属于无害垃圾，未处理。
6. **进入设置页后焦点停在顶栏 Tab 上**，需多按一次 ↓ 才落到第一行（本次操作中撞到）。不影响功能，属手感瑕疵。
7. **书架卡片名随备注名变化**：代码路径已确认，但 314 张卡里没滚到目标卡，**未实拍**。
